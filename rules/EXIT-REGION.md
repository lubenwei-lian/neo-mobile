# 出口地区检测

## 用户行为

“设置 → 通用 → 出口地区”查询每个节点的出口国家或地区，不把订阅中的节点名称当作检测结论。点击开始后立即显示准备、等待、检测进度或停止状态；标题点击效果限制在圆角内。

默认跳过 7 天内的有效记录。新结果显示“出口：日本”等；过期、迁移或刷新失败的记录显示“上次：日本”，没有记录则显示“出口未确认”。停止或离开页面会取消任务，已经完成的结果保留。

地区结果来自查询服务的 IP 数据库，只表示本次观察到的出口归属，不保证节点物理位置，也不参与实际流量分流。

## 职责

| 模块 | 职责 |
| --- | --- |
| `RegionDetectionPanel` | 设置卡片、圆角交互、进度展示与页面生命周期 |
| `RegionDetectionController` | 开始、停止、重复启动保护、网络或配置变化取消、完成状态 |
| `RegionDetector` | 构建待测列表、物理节点去重、逐节点检测与结果提交 |
| `ProbeCoordinator` | 测速与地区查询共用的单会话调度，节点之间优先安排等待中的测速 |
| `RegionLookupRequest` / `RegionLookupResponse` | HTTPS 请求、响应校验、回退与地区变化复核 |
| `ExitRegion` / `RegionCacheStore` / `NodeRegionCache` | 统一国家码、历史状态、持久化与 StateFlow 通知 |

每次只检测一个物理节点；节点清理完成后才让出会话。取消等待的测速会撤销排队计数；取消地区检测会清理当前会话。UI 不持有请求和缓存实现。

## 请求与确认

主服务为 `https://ipwho.is/`，备用服务为 `https://api.country.is/`。连接、TLS、响应、回退以及可选的地区变化确认共享 8 秒总预算；首次主请求最多使用一半预算，为回退留出时间。响应体最多 64 KiB，仅接受有效 ISO 国家码。

首次查询或与历史国家码相同时可以采用单服务结果。如果国家码变化，则要求两家服务在同一次检测中观察到同一出口且国家码一致；出口变化、分歧或无法复核时保留历史。用于比较的出口指纹仅在内存中使用，不写入缓存或日志。

HTTP 429 触发查询服务级冷却：`Retry-After` 限定为 5～600 秒，默认 60 秒，使用单调时钟。超时、限流、网络异常、无效响应和地区变化未确认均保留明确的失败状态。

## 缓存

`files/node_regions_v3.json` 保存哈希身份、国家码、来源、成功时间、确认级别及可选的最近失败原因和时间，不保存出口 IP。有效期 7 天、历史保留 30 天，最多 2048 条记录。

可识别的 v2 中文或英文国家名称迁移为待刷新的历史记录，不冒充本次检测结果。仅写 v3，不改旧文件；损坏的 v3 可以从 v2 恢复。刷新失败不覆盖上次成功国家码和时间。

## 节点页国旗修复

2026-11-06 发现 v3 缓存使用大写 ISO 国家码，而既有国旗绘图分支使用小写，导致已确认地区的节点显示灰色圆形。在 `NeoFlagBadge` 入口使用 `Locale.ROOT` 统一大小写后，实机确认日本和新加坡国旗恢复；413 项候选单元测试通过。

一加测试版已更新，最终主页显示已连接、网络可用，原选中节点未变，测速和地区缓存均保留 60 条。安装脚本首次完整状态相等检查未通过（重连后配置已重新生成），后续单独核验了安装包、当前节点、连接、缓存数量及国旗画面；没有据此宣称所有内部状态完全相同。验证记录位于 `routing-20261106-region-flags-hotfix` 归档，未发布。
