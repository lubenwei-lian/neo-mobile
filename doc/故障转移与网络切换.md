# 故障转移与网络切换

本文说明 Android 端的节点选择策略、断流自动切换与网络变化处理。

## 一、关闭并发模式

多节点并发在本项目的实测与 Windows 端经验中并未带来稳定收益（并发开销与出口分散使单连接速度反而下降），Android 端采用单节点 + 故障转移的稳定路线。

| 位置 | 改动 |
|---|---|
| `bg/BalancerInjector.smali` | `concurrentEnabled()` 恒返回 false（不再读数据库开关） |
| `compose/screen/settings/SettingsScreenKt.smali` | 设置页不再显示「并发模式」开关 |
| `AndroidManifest.xml` | 使用 `networkSecurityConfig`，默认禁止明文，仅放行 127.0.0.1/localhost |

`ensure()` 本身带开关分支（关闭时原样返回配置），因此注入路径不会执行，后续需要时可恢复。

## 二、断流自动切节点（FailoverGuard）

新增 `02-java/patches/FailoverGuard.java`（只依赖 `java.*` 与 `org.json`），编译进 `classes4.dex`。

工作方式：

- 内核启动成功后 `FailoverGuard.start()`；会话结束 `stop()`（两处清理路径都挂钩）。
- 每 20 秒请求 Clash API：`GET /proxies/{组}/delay?url=generate_204&timeout=6000`。
- 连续 3 次失败（-1 / 超时）后，遍历组内候选逐个测延迟，选第一个可用的，`PUT /proxies/{组}` 切换。
- 切换后 90 秒冷却，避免来回抖动。

约束：

- 只走 loopback HTTP（127.0.0.1:9091，回落 9090），不走 TUN、不改内核配置。
- 组名自动发现：优先含「节点选择 / Proxy / PROXY」的 Selector，否则取第一个 Selector。
- 候选排除 Selector / URLTest / Fallback / LoadBalance 组，只认真实节点。
- API 不可用时静默待命，不报错、不重试风暴。

## 三、网络切换监听（NetworkWatcher）

`02-java/patches/NetworkWatcher.java` 注册 `ConnectivityManager.NetworkCallback`（NET_CAPABILITY_INTERNET），网络可用/丢失时通知 FailoverGuard。

FailoverGuard 收到唤醒后等待 2.5 秒系统稳定期再探测，避免切换瞬间误判。Context 通过反射获取（`Application.Companion.getApplication()`），编译期不依赖应用侧 Kotlin 类。

运行日志示例：

```
I/NeoNetWatcher: network watcher started
I/NeoNetWatcher: network changed: available
I/NeoFailover: wake by network change: available
```

## 四、验证

| 判据 | 结果 |
|---|---|
| 设置页无「并发」字样 | 通过（UI dump 无匹配） |
| 内核配置不注入 balancer | 通过（outbounds=36，balancer=0） |
| 路由回到订阅原配置 | 通过（`route.final` 为节点选择组） |
| 连接可用 | 通过（约 1.5 秒连上） |
| 守卫随内核启动 | 通过（日志可见） |
| 探测循环运行 | 通过（每 20 秒一轮，正常时静默） |
| 失败/恢复检测 | 通过（probe failed / recovered 日志） |
| 切换 API 协议 | 通过（手工 PUT 组名 → 204，出口立即变化） |
| 连续 3 次失败触发切换 | 代码与协议层验证；未在真实断流中凑满 3 连败（上游 urltest 会自行切走） |

## 五、踩坑

1. **VerifyError: register index out of range**：改写 `concurrentEnabled()` 时 `.locals 0` 却使用 v0，校验失败，连接时崩溃；改为 `.locals 1`。
2. **明文 HTTP 被系统拦截**：Android 9+ 默认禁止 cleartext；改为 `networkSecurityConfig` 只放行回环明文。
3. **KernelSU 的 su 语法**：`su -c` 可读文件但执行 iptables 报 Permission denied，需 `su 0 sh -c`。

## 六、回滚

- 恢复并发：把 `concurrentEnabled()` 改回读取数据库开关，并恢复设置页开关项；
- 关闭故障转移：移除 `FailoverGuard.start()` 挂钩点，或直接安装上一版 APK。
