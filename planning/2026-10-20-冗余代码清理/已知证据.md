# 已知证据

## 关键证据
1. **「语言」块不可删（实测）**：删除 lambda$107$0 内 L4933-5325 后，装机点「应用」→
   `java.lang.VerifyError: Verifier rejected class AppSettingsScreenKt: AppSettingsScreen$lambda$107$0 ... [0x199] register v2 has type Precise Reference: ry but expected Reference: android.content.Context`
   → FATAL EXCEPTION → Process has died。回退后正常。
2. **apktool 增量缓存坑（实测）**：只改 smali 后重编译，apktool 会输出 "smali has not changed." 并**复用旧 dex**。
   证据：49/50/51 三个 unsigned APK 大小完全相同（36120956），而回退后 52 版为 36121255，
   且 build/apk/classes.dex 的 mtime 停留在 50 版构建时刻。
   ⇒ **每次改 smali 后必须删 01-apktool\build 再编译**。
3. **wu5 是跨模块共享 lambda 工厂**：packed-switch 0x0..0x1c，涉及 ToolsScreenKt / Tailscale* /
   SettingsScreenKt 等，删整类会崩溃 → 不可删。
4. **zn 同样共享**：AppSettingsScreenKt L2702 用 ID=0x0（pswitch_2 → V0 → lambda$107$1），
   该实例用于 NeoPanel 的 onClick（Tailscale 卡片），不是 Ghostty 行渲染 → 分支仍可达，不可删。
