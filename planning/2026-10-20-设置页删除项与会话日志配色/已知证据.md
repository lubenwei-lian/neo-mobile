## 四、bug 根因【事实，指令级】
位置：`01-apktool\smali\io\nekohasekai\sfa\compose\screen\settings\SessionLogScreenKt.smali`
方法：`SessionLogDetailScreen$lambda$18$3`（L5201-5402）

```
L5326    const-wide/16 v4, 0x0        ← 颜色参数传成 0
...
L5378    invoke-static/range {v2 .. v23}, La07;->b(Ljava/lang/String;Lub4;JJLri2;...)V
```

对照同一渲染器 `a07.b` 内部（`02-java\sources\defpackage\a07.java:544-560` 附近）：

```java
long j11 = j;                       // 传入的颜色
if (j11 == 16) {                    // 0x10 == Color.Unspecified
    jB = c17Var3.b();               // 回退到主题内容色

```

⇒ **只有传入 `0x10`（Unspecified）才会回退主题色**；传 `0x0` 就被当成"纯透明黑"直接使用 → 暗色背景上显示近黑字。

对照正常调用（同项目其它 `a07.b` 调用）传的是 `0L`，但那些调用第 3 参后还有 `((io0) rn2Var.j(lo0.a)).s` 之类显式取色；本处**第 3、4 参都是裸 0**，没有任何主题取色。

## 五、最终修复（实测通过）

### 我的第一版修法【无效，留痕】
只把 `0x0` 改 `0x10` → 实测亮度仍 13.5、**零变化**。原因见下。

### 真根因（两处叠加）
1. **默认参数掩码覆盖**：调用点掩码 `0x3ff6c` 的 **bit2(值 4)** 置位，Kotlin 语义 =「颜色未提供」，
   → 传入的颜色（无论 0x0 还是 0x10）**被完全忽略**。
2. **Unspecified 不是主题色**：`0x10` 会回退到 `LocalContentColor`，其默认在暗色下就是**近黑**。

### 最终修法
1. 掩码 `0x3ff6c` → `0x3ff68`（清 bit2，让颜色真正被采用）
2. 颜色改为**显式取主题 onSurface**：`lo0.a` → `rn2.j()` → `io0.s`

### 决定性证据：哨兵实验
先把颜色临时改成**白色**(`do0.e`)：亮度 **255**、亮像素 **40127**
⇒ 证明**调用点确实生效**，问题只在颜色取值；随后换 onSurface 得 154.6。

## 八、方法与踩坑（本轮新增）
1. **最大坑**：把 jadx **java 行号当 smali 行号** → 定位错一次、白改一版。正确做法是在 smali 内按资源键定位。
2. 掩码覆盖：改了颜色但掩码声明「用默认值」→ **静默无效**；改 Compose 参数前必须自查掩码。
3. smali 4 位寄存器限制：`.locals 24` 方法内 `invoke-virtual {v2, vN}` 只能 v0-v15；用 v21 会编译报错。
4. 注释不进 dex：不能用注释字符串验证改动是否打包成功，要反编译或看 dex 字节差。
