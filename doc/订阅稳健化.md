# 订阅稳健化与 legacy DNS 迁移

## 一、问题

部分订阅服务商（v2board 模板）在判定账号设备超限后，不再返回 403，而是返回一份只含 3 个「提示节点」的配置（tag/名称形如「使用的设备过多」「请去官网获取新订阅链接」「官网地址:…」）。旧版客户端会照单全收，把原本可用的配置覆盖成这 3 个假节点，用户表现为「更新失败/内容无法解析」或莫名连不上。

另一类兼容问题：服务商会按 User-Agent 中的 sing-box 版本决定返回新格式还是 legacy DNS 格式。客户端 `version()` 恒为 `unknown` 时，服务端持续下发 legacy DNS（顶层 `dns.fakeip` 字段）；sing-box 1.12 起弃用、1.14 已移除该格式，加载即失败。

## 二、SubGuard

新增 `io.neoguard.SubGuard`（`02-java/patches/SubGuard.java`，只依赖 `java.*` 与 Android 内置 `org.json`），编译进 `classes4.dex`，在两处 `checkConfig` 前调用。

| 改造 | 实现 |
|---|---|
| 识别「提示节点」订阅并拒绝覆盖 | `SubGuard.prepare()`：先 check，再按需做 DNS 迁移；命中提示语时抛出可读错误 |
| 版本号 | `SingBoxKernel.version()` 返回真实版本（`1.14.3`），不再返回 `unknown` |
| legacy DNS 自动迁移 | `SubGuard.migrate()`：仅在检测到 legacy 格式时做等价改写，失败原样返回 |
| 自动更新最勤间隔 | 60 分钟 → 12 小时 |

### 2.1 判定规则（`SubGuard.check`）

1. 文本命中提示语（`使用的设备过多` / `请去官网获取新订阅链接` / `官网地址` / `套餐已到期` / `流量已用尽`）→ 拦截；
2. 能解析成 JSON 且含 `outbounds`：
   - 任一 outbound 的 `tag` 命中提示语 → 拦截；
   - 真实出站（type 不是 direct/block/dns/selector/urltest）数量 > 0 但**全部指向 127.0.0.1 / localhost / ::1 / 0.0.0.0** → 拦截；
3. 其余放行，交给内核 `checkConfig` 校验。

> JSON 中的中文是 `\uXXXX` 转义，文本层匹配不到，因此同时依赖解析后的 `tag` 命中。

### 2.2 拦截后的行为

- 不写配置文件（`checkConfig` 前抛异常，上层弹窗提示；fetch 路径直接失败不落盘）；
- 提示文案：`机场返回的是提示节点（使用的设备过多），不是真实节点；已保留原配置`。

### 2.3 legacy DNS 迁移规则

| legacy | 新格式 |
|---|---|
| `{"address":"local"/"fakeip"/"hosts"/"dhcp"}` | `{"type":"local"/"fakeip"/...}` |
| 顶层 `dns.fakeip{inet4_range,inet6_range}` | 合并进 `type=fakeip` 的 server |
| `{"address":"1.1.1.1"}` | `{"type":"udp","server":"1.1.1.1"}` |
| `{"address":"https://host/path"}` | `{"type":"https","server":"host","path":"/path"}` |
| `address_resolver` | `domain_resolver` |
| 缺 `route.default_domain_resolver` | 补 `"local"` |

迁移只在检测到 legacy 时触发；迁移后的配置若被内核拒绝，自动回退原文再校验一次。

## 二点五、订阅拉取顺序（0.0.3 修复）

`SubscriptionFetcher` 原先分支写反：直连失败时跳过内核 HTTP 回退，直接对 null 调 `getBytes`，表现为「添加订阅 → 错误 → Attempt to invoke ... on a null object reference」。0.0.3 改为：直连成功直接用直连内容；直连失败（包括 Android 明文 HTTP 策略拦截）才回退 `HTTPClient`。真机用 LAN HTTP 订阅复现并验证修复。

## 六、已知限制

1. 提示节点判定是启发式（关键字 + 全本机地址），服务商更换文案时需要补充 `SubGuard.HINTS`。
2. 版本号 `1.14.3` 是常量（内核未注入真实版本），与内核实际版本未做交叉验证。
3. 迁移只做等价改写，无法修复订阅本身与内核不兼容的其它字段。
4. 设备超限是服务端状态，客户端只能做到「不覆盖原配置」，不能解除限制。

## 七、回滚

安装上一版 APK 即可恢复旧行为。
