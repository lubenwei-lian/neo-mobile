## 实证

1. 原独立 CLI 探测复制了节点的 `domain_resolver: local`，运行时访问 `[::1]:53` 并被拒绝。SOCKS greeting 成功，但 CONNECT 返回 5。主 VPN 同时能连接多个国内和海外 TLS 目标，因此“测速失败”等同“节点不可用”的判断不成立。
2. 保持同一物理 VLESS 节点，只将独立进程的 local DNS 改为明确的 HTTPS DNS `223.5.5.5`，SOCKS CONNECT 返回 0。HTTP Cloudflare 探测返回 403、gstatic 返回 204；两者 HTTPS 均校验证书并返回 204。不能把这个 HTTP 403 推广为所有地区或节点的行为。
3. `ProbeConfigBuilder` 仅保留请求节点和必要的出站/DNS 依赖；不带主 TUN、控制端口、缓存、路由规则或无关机场 urltest。仅独立进程替换 Android local DNS，不改变主 VPN 的节点 DNS 或游戏分流。节点 TLS、transport、显式不安全设置和 detour 原样保留。
4. 真机诊断包的单节点探测实际返回 145 ms，页面却显示另一个值。节点行从普通缓存读数，父层增加 cacheVersion 不能保证 Compose 重绘参数未变化的子行；机场后台 group history 也在写同一缓存。修复为显式传递 delay/testedAt/insecure 参数，并只让 Neo 自身测速更新该页面缓存。

## 修复范围

- 独立 CLI DNS 和依赖裁剪；探测改用校验证书的 HTTPS，仅 204 计成功。
- SOCKS 建连失败时关闭已分配的 socket；测速会话串行化。
- 单节点操作有已有样式的进度反馈；全部失败不再显示“最快 0 ms”。
- 持久诊断记录配置/监听/测量/完成阶段及数值，不记录节点名称、地址或认证字段；不再向 logcat 输出独立核心原始日志。
- 这是网页连通延迟，使用 TCP/UDP 外层协议的节点均访问 HTTPS。不是游戏 UDP 延迟或进入正式对局的保证。
