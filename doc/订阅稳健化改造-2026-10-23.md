## 一、要解决的问题

赔钱机场（dasho.pqjc.site）判定账号设备超限后，**不再返回 403，而是返回一份只含 3 个「提示节点」的配置**：

```
shadowsocks | 使用的设备过多          server=127.0.0.1
shadowsocks | 请去官网获取新订阅链接   server=127.0.0.1
shadowsocks | 官网地址:https://赔钱机场.com  server=127.0.0.1
```

旧版客户端照单全收，会把原本能用的配置**覆盖成这 3 个假节点**，用户只看到「更新失败/内容无法解析」或莫名连不上。

## 二、四项改造

| # | 改造 | 实现 |
|---|---|---|
| 1 | 识别「提示节点」订阅，**拒绝覆盖**并给中文提示 | 新增 `io.neoguard.SubGuard`（classes4.dex），在两处 `checkConfig` 前调用 `checkOrThrow()` |

| 4 | 自动更新最勤间隔 60 分钟 → **12 小时** | `UpdateProfileWork$Companion` 里 `const-wide/16 v0, 0xf` → `0x2d0`（15 → 720 分钟） |

### 2.1 判定规则（SubGuard.check）

1. 文本命中提示语（含 `使用的设备过多` / `请去官网获取新订阅链接` / `官网地址` / `套餐已到期` / `流量已用尽`）→ 拦截
2. 能解析成 JSON 且含 `outbounds`：
   - 任一 outbound 的 `tag` 命中提示语 → 拦截
   - 真实出站（type 不是 direct/block/dns/selector/urltest）数量 > 0 但**全部指向 127.0.0.1 / localhost / ::1 / 0.0.0.0** → 拦截
3. 其余放行，交给内核 `checkConfig` 按原逻辑校验

> JSON 里的中文是 `\uXXXX` 转义，所以文本层匹配不到，靠解析后的 `tag` 命中（实测日志：`hint=null` → `tagHit=使用的设备过多`）。

### 2.2 拦截后的行为

- **不写配置文件**（Dashboard 路径在 `checkConfig` 前抛异常，被上层 catch，弹窗提示；fetch 路径 outcome.ok=false，`UpdateTask` 直接 throw，不落盘）
- 提示文案：`机场返回的是提示节点（使用的设备过多），不是真实节点；已保留原配置`

## 六、已知限制 / 未解决

1. **赔钱机场订阅本身与 1.14 内核不兼容**：即使解除设备限制，它返回的配置仍用 legacy DNS fakeip，`checkConfig` 会报
   `legacy DNS fakeip options are deprecated in sing-box 1.12.0 and removed in sing-box 1.14.0`。
   现有 `configs/8.json` 能用只是因为「内容没变过、从未重新解析」。
   → 本次改动能让它**不覆盖**，但**不能让这个订阅恢复可用**（除非机场换新格式，或另写迁移器）。
2. 「提示节点」判定是**启发式**（关键字 + 全本机地址）。机场若换文案（如「超限」），需要往 `SubGuard.HINTS` 里加词。
3. 直连拉订阅在部分网络下可能失败（被墙/需代理），当前**没有**「直连失败再走代理」的兜底。
4. 版本号 `1.14.3` 是**写死**的（libbox.so 未注入真实版本），与内核实际版本未交叉验证。

# 追加（2026-10-23 22:0x）：fakeip「隐患」的根因与修复

## 八、根因：机场按 UA 里的 sing-box 版本号决定返回哪种 DNS 格式

A/B 实测（同一订阅 URL、同一时刻，只改 UA）：

| UA | dns 顶层字段 | servers[0] | 体积 |
|---|---|---|---|
| `SFA (sing-box 1.14.3; language zh_CN)` | `servers, rules, final`（**新格式**） | `{"type":"local","tag":"local"}` | 271,922 B |
| `SFA (sing-box unknown; language zh_CN)` | `servers, fakeip, rules, final`（**legacy**） | `{"address":"fakeip","tag":"fakeip"}` | 271,783 B |

**结论**：赔钱机场（v2board 定制模板）会解析 UA 里的 `sing-box <版本>`，≥1.12 就下发新 DNS 格式，识别不出就退回 legacy。
手机版原来 `version()` 恒为 `unknown`（libbox.so 编译时没注入 tag）→ 机场一直下发 legacy → 一更新就撞 `legacy DNS fakeip ... removed in 1.14.0`。

**修复**：`SingBoxKernel.version()` 返回真实版本 `1.14.3` → UA 变成 `SFA (sing-box 1.14.3; language zh_CN)` → 机场直接下发新格式。
实测手机日志：`migrate: servers=7 fakeip=false legacy=false` —— 内容已经是新格式，fakeip 问题消失。

## 九、兜底：legacy DNS 自动迁移器（SubGuard.migrate）

针对「不按 UA 适配」的其它机场，拉取后自动做等价改写（只在检测到 legacy 时触发，失败原样返回）：

| legacy | 新格式 |
|---|---|
| `{"address":"local"/"fakeip"/"hosts"/"dhcp"}` | `{"type":"local"/"fakeip"/...}` |
| 顶层 `dns.fakeip{inet4_range,inet6_range}` | 合并进 `type=fakeip` 的 server |
| `{"address":"1.1.1.1"}` | `{"type":"udp","server":"1.1.1.1"}` |
| `{"address":"https://host/path"}` | `{"type":"https","server":"host","path":"/path"}` |
| `address_resolver` | `domain_resolver` |
| 缺 `route.default_domain_resolver` | 补 `"local"` |

验证：把 dasho 原始 legacy 配置按该规则转换后，用桌面 `sing-box 1.14.3 check` 校验 **exit=0**（转换前 exit=1，报 fakeip）。

关掉并发模式后重新拉，机场仍返回 3 个占位节点。说明超限是**机场侧状态**（不是即时解除）。

- 关掉「并发模式」（原来 8 节点池并发连 → 同账号多个出口 IP 同时在线，是超限的可疑放大器；【推断】）
- 订阅拉取改直连、12 小时才拉一次、UA 不再 unknown
