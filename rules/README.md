# Neo 规则维护

Neo 自己编译路由和 DNS，机场订阅只提供节点及其连接依赖。普通用户无需编辑规则。

处理顺序：用户覆盖 → 私网 → 已验证应用/游戏策略 → 明确海外域名 → 国内域名 → 国内 IP → 未知公网代理。
主代理选择器仅包含实际代理节点，避免机场的 DIRECT、REJECT 或自动测速组改变代理兜底。

## 新增游戏

先记录包名、区服、网络、实际节点摘要和验证时间，再对照冷启动登录、正式对局、返回大厅重新匹配、重启游戏。
全部走代理的游戏使用 `apps[].mode = global-proxy`。国内外分流应用使用 `domestic-split`。
需要战斗分流的游戏使用 `games[].matches`，必须按包名限定；不得把 PUBG 的 UDP 直连扩散为全局规则。
DNS 使用游戏显式的 `dns` 兜底。只有不限定网络和端口的域名例外才同步改变 DNS；UDP/TCP、目的端口或端口范围的例外只作用于相应连接，不扩大成整个域名的 DNS 规则。`domains` 与 `cidrs` 沿用内核的地址备选语义，不代表两者必须同时命中。

同一例外中的 `ports` 与 `portRanges` 也是备选条件；地址组和目的端口组各自 OR，再与包名、网络等条件做 AND。不要把测试求值器当作完整内核：未支持条件必须明确失败，二进制规则集和 Android 包名归属需要原生验证。
未经过验证的策略保持 `verification = candidate`，不能进入正常连接或更新资产。
策略格式见 `app/src/main/java/io/nekohasekai/sfa/policy/NeoPolicy.kt`；规则测试在 `app/src/test/java/io/nekohasekai/sfa/policy`。

IP 地区不能判断业务用途。新的特殊游戏必须采集证据维护策略，不能声称软件能自动准确识别任意游戏。

## 规则数据更新

1. 取得可信来源的 `geosite-cn.srs`、`geoip-cn.srs`，记录来源版本和摘要。不要使用用户订阅里的分流规则。
2. 可选准备策略 JSON，填写独立版本、包名、验证状态和日期。
3. 执行 Android 回归测试，并在测试机上使用内置内核检查新资源及实际分流。
4. 从当前线上 `update.json` 生成本地候选：

```powershell
node tools/prepare-routing-update.cjs --manifest <当前清单> --asset-base-url <HTTPS版本目录> --output-dir build/routing-release --geosite-cn <域名SRS> --geosite-cn-version <独立版本> --geoip-cn <IPSRS> --geoip-cn-version <独立版本> --policy <策略JSON>
```

工具检查文件头、大小、版本和策略基本结构，生成版本化资产及 SHA-256；不会上传。完整结构和内核兼容性由 Android 编译器和内置内核检查，文件头通过不代表规则语义正确。
没有变更的资源可以省略，当前应用更新元数据及其他资源声明会保留。同一版本的内容不可修改。工具同时核对当前清单中的同版本摘要/大小及输出目录中的已有文件；换空输出目录也不能绕过当前清单的同版本检查。修改文件内容（包括策略 JSON 的字节格式）必须递增资源版本；内容相同时可以迁移下载地址。

5. 真机验收后上传资产，确认公开下载的大小和摘要正确，再更新清单；保留上一版资产和清单用于回退。

客户端只在首次确认代理可用后检查一次。下载失败不影响当前连接；全部目标资源校验完成后一次性暂存。
检查由应用任务持有：关闭任务取消检查和HTTP连接，旧页面销毁不得取消新任务。新任务等待旧检查清理后再下载；取消不继续切镜像，也不发布迟到结果。进入同步原子暂存前检查取消，已开始的有效原子暂存允许完成。一加实际HTTPS取消、同任务重连与定向任务移除重开已验收，操作边界和证据见`DIAGNOSTICS-20261106-UPDATE-DEVICE.md`；未Root设备和完整线上OTA仍待验收。
新规则只在下一次连接验证启用，启动失败自动回退；进行中的对局继续使用不可变资源文件。
内核或编译器拒绝的规则集/策略候选会被丢弃，继续使用已确认版本，并在现有原子状态中保存最多 16 条退避记录。同一应用版本号下，自动下载在 24 小时内跳过被拒绝的策略版本或规则集“名称 + 版本 + SHA-256”；新版本和应用升级后允许重新验证。时钟回拨不会造成永久隔离，取消验证和启动阶段的临时回滚不会把正常资源记成坏版本。此机制是限时重试退避，并非永久隔离或清单签名。
策略下载的大小和 SHA-256 均核对后，JSON/结构无效、版本不一致和未验证条目也会进入同一退避。摘要不匹配、截断、非法清单和存储失败不会记成坏策略；已确认版本及其他待验证候选保持。新增路径的 `PolicyAssetStagerTest` 必须通过发布门槛，电脑回归不等于远端下载流程已在真机验收。
APK 升级刷新仍在使用内置版本的规则和应用策略，已确认的下载版本保留；来源与回滚状态一并记录，避免旧缓存阻挡内置策略升级。
客户端目前通过 HTTPS、大小和 SHA-256 校验数据，尚未实现独立的清单签名机制。
策略与 SRS 下载共用受限读取器，最多读取清单声明大小加 1 字节，超长、截断或无进展会立即失败。镜像按真实 GitHub host 判断，候选必须保持 HTTPS，拼接不得改变镜像 host。
客户端也会拒绝 current/candidate/previous 中同版本但语义不同的策略，以及同名同版本但摘要不同的已下载规则集；规则集冲突拒绝整批暂存。这是保留快照内的一致性保护，不等于记录全部历史版本。

## 构建与发布

测速必须延续实际连接的 DNS 来源。独立 CLI 无 Android 平台接口：Android 10+ 对连接图引用的 local DNS 使用窗口内回环桥，由 Android 在非 VPN 物理网络执行解析；显式 DoH 不改。回环桥只允许连接图入口/探测目标的 A/AAAA，校验回复，限制在途查询，并在停止、换网络、离页和关闭窗口时取消。旧系统保留 DoH 兼容路径，兼容 worker 当前保持既有路径，分别验收，不混用性能证据。当前 native 指标为已验证 HTTPS 的网页响应中位数，节点内部短期复用连接；DNS/隧道/TLS 仍占整体期限，但不计入响应数字，调试单测另记首连阶段。新响应缓存与旧完整建连、兼容内核指标隔离，界面说明测量定义，不与游戏 RTT 或带宽互换。发布门槛包含 `ProbeDnsQuestionTest` 和 `ProbeHttpResponseTest`；历史 DNS 证据见 `DIAGNOSTICS-20261106-SPEED-LOCALDNS.md`，当前响应测速证据见 `DIAGNOSTICS-20261106-SPEED-RESPONSE.md`。

`tools/build-android.ps1` 直接构建当前工程，用临时盘符映射处理 Windows 中文路径。发布工具不再调用旧工程镜像脚本。
`-Properties '-PneoRoutingTest=true'` 生成 `com.xiaosaik.neo.routingtest` / `Neo 分流测试`，避免覆盖原版。
该测试构建可以读取自身私有目录的 `files/neo-policy-preview.json`，验证尚未确认的游戏策略。文件必须是 `preview-` 版本的策略包，所有条目保持 `verification = candidate`；它不会写入正常策略仓库，也不能通过更新接口发布。
预览仅在 DEBUG、`ROUTING_TEST` 编译开关及测试包名同时匹配时生效。正式构建的开关为 false，忽略该文件；普通调试包默认也不读取。删除预览文件后，在游戏空闲时重新连接恢复正常策略。对照实验必须记录实际编译规则、节点摘要和策略仓库未被修改的证据。
自动更新检查的开始和返回状态记录到已有的本地诊断日志，不记录节点、订阅或更新地址，用于区分“没有触发”和系统 logcat 已轮换。
正式包必须使用原签名。仅有电脑测试通过不能发布为游戏稳定版本。
发布准备要求网络健康、连接恢复、路由场景、策略仓库、规则集回滚、资源校验与更新清单等回归报告全部通过，同时检查规则维护工具测试。

## 测速与出口地区检测

测速使用已验证 HTTPS 的响应中位数，不含首次握手，不代表游戏延迟。批量检测按入口限制并发，不切换正在使用的节点。地区按实际出口查询，提供自动备用服务、进度与停止；按配置身份缓存 7 天，订阅同名节点不会借用旧记录。查询失败不会猜测地区或覆盖有效结果。验证范围见 [测速与地区检测记录](DIAGNOSTICS-20261106-SPEED-REGION.md)。

失败节点按轮次交替 HTTPS 测速目标，单节点也保留一次备用优先重试，采样次数、成功多数门槛、TLS 校验和每轮期限不变。数据与局限见 [测速目标重试记录](DIAGNOSTICS-20261106-SPEED-TARGET-RETRY.md)。
